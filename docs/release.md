# Phase-1 packaging and release

## Targets

Initial x64 baselines: Ubuntu 24.04 LTS and Windows 11. Produce Linux AppImage and deb, Windows NSIS installer. Other Linux distributions and Windows 10 are unverified until independently tested. macOS/ARM are out of scope.

Prefer target-OS native build runners because better-sqlite3 is native. A cross-generated installer is not proof of execution. Use the exact Electron ABI rebuild settings for the pinned builder. Keep runtime dependencies bundled; use userData for writable files. Application code/assets must be self-contained.

## Build and installation checks

Clean lockfile install -> type/lint/test -> bundled production build -> OS package -> install/launch -> SQLite write/reopen -> full offline local-API smoke story. Set publish disabled; do not upload or distribute automatically. No auto-update or telemetry.

Unsigned internal installers are acceptable for phase 1. Document potential Windows reputation prompts; do not claim code signing. Never advise disabling antivirus or system protections. Linux packaging must document distro prerequisites and use normal Electron sandbox configuration, not `--no-sandbox`.

Installer/uninstaller must not silently delete user workspaces. Preserve local userData on uninstall by default; provide documented path and explicit manual removal instructions for users who want full deletion. Avoid destructive commands in ordinary setup instructions.

## Release deliverables generated by implementation tasks

- Linux/Windows installable packages with version and SHA-256.
- `docs/toolchain-lock.md` with verified package/build versions.
- `docs/release-acceptance.md` with independent actual results for both OS targets.
- `docs/user-guide.md`: installation, workspace/request/variable workflow, save/draft behavior, secrets capability, upload re-selection, import/export limits and data location.
- `docs/known-limitations.md`: actual remaining issues and deferred features.

Do not mark phase 1 release-ready if either platform required checks are not run or fail. Coding completion and release verification are different states.
