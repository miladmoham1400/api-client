# Offline API Client 0.4.0

Selectable request bodies, assisted variable/JSON editing and Postman collection transfer, in the dark glass desktop client. Unsigned pre-release for Linux and Windows. Existing workspaces and saved requests remain supported.

## New in this release

- Keep multiple named Body variants for a request, select one and send its content without repeatedly rewriting your test payload. Variants survive saves/restart, duplication and native workspace transfer.
- Variable placeholders are colored, with suggestions from the current workspace/effective environment. Arrow keys choose, Enter/Tab accepts and Escape dismisses. Sensitive values are never revealed for completion; password fields remain masked.
- JSON Body formats on blur without rounding large numbers or replacing template expressions. Invalid JSON stays unchanged, with line/column hints that remain visible after switching editor tabs.
- Copy the exact original response with a small button beside the metrics. Ordinary JSON starts expanded; users can collapse irrelevant sections. Large/deep responses keep bounded lazy/Raw fallbacks.
- Import Postman Collection v2.1 JSON into a new workspace with a validated preview; export a selected collection, including nested folders, to Postman v2.1 JSON. Body examples become named variants. Import and Export now have clear labeled toolbar actions and distinct icons.
- Retains local SQLite persistence, autosave, nested API library/search, safe static HTML previews, themes and adjustable request/response panels. No automatic request sending or runtime cloud dependency.

## Transfer and editing limits

Postman support is a documented subset of Collection v2.1 JSON, not v2.0/v3/YAML or full Postman runtime compatibility. Scripts/tests, response payloads and descriptions are not imported or executed. Unsupported auth/body/method/path/folder-variable/proxy/certificate/protocol options reject before writing; OAuth is not supported. Credential literals, credential headers, sensitive variable values and local upload paths/selections are omitted; re-enter values and select files locally. Only workspace-level variables transfer on export; environment-specific values and app timeout/redirect settings do not. Ordinary URL/query/body/plain-variable text may contain user-entered secrets: review exports before sharing.

Body variants are bounded to 20 and 10 MiB aggregate; format/response work is bounded for responsiveness. Native files with the new profile fields may be rejected by older strict app versions; import them with 0.4.0 or newer. Autosave is not recovery from abrupt process termination.

## Downloads and verification

Choose `.deb` for Ubuntu 24.04 x64, `.exe` for Windows x64 or `.AppImage` for Linux x64, and verify `SHA256SUMS.txt`. Installed use requires no developer Node/npm or account.

Publication requires fresh native Ubuntu 24.04 and Windows Server 2022 builds of one source commit, all unit checks, actual deb/NSIS installation, and focused installed-app tests including Body variants, exact wire behavior, clipboard copy, variable completion and Postman file transfer. The publisher verifies source provenance and installer hashes before upload. Source/build commit: `93ebf92e3679d33d105693c9cad0ad778ed60ece`. - With 1,000 requests and 1,000 folders, cold readiness / selection p95 / search p95 measured 1229.83 / 241.57 / 155.12 ms on Linux and 1258.29 / 259.89 / 152.92 ms on Windows, within the unchanged existing thresholds.

Hosted Windows Server checks do not establish Windows 11 acceptance. Full network-isolated/manual chooser and uninstall/reinstall acceptance has not been repeated for these installer bytes; default AppImage FUSE launch and actual Postman GUI import are not verified here. File-service integration tests use controlled native chooser responses. Packages are unsigned and Windows may show reputation prompts.
