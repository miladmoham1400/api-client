# Offline API Client 0.5.0

Response testing, refined glass controls and smaller installers for the offline desktop API client. Unsigned pre-release for Linux and Windows.

## Changes

- Save literal expected response JSON separately for each named Body variant. Each Send automatically checks the captured expectation and displays pass, changed or unavailable.
- Differences use readable paths such as `data.scores_headers`. Open an initially collapsed change to see complete colored pretty JSON with readable Persian/Unicode and exact numeric tokens. Object order/whitespace are ignored; array order, missing fields, types and values are significant.
- Clear guidance for bodies with no saved expected JSON. Invalid/non-JSON, binary, cancelled, failed and over-limit responses report unavailable. Expected samples persist locally and duplicate with requests; default native/Postman exports omit them.
- Request tabs above the editor/response retain bounded session presentations, with guarded navigation/closing and no automatic sends. Closing a tab keeps the saved request. Tabs/results clear after restart or workspace changes.
- Pretty response JSON starts fully expanded within the existing supported size bounds; nodes remain manually collapsible. Body and response corners match.
- Glass dropdowns and context menus with selected checkmarks, themed hover/focus, readable long labels and keyboard support. Escape dismisses an open picker before its dialog.
- Balanced Request editor tab padding and fixed rounded corners, with soft color feedback on hover.
- Smaller runtime payload and stronger compression for Linux deb/AppImage and Windows full NSIS installers, retaining SQLite, sandbox, Unicode/ICU, graphics resources and dependency legal notices.

## Use and limits

In **Body → Response test**, enter expected JSON and select **Save expected JSON**. Checks compare the sample captured at Send, even if the editor changes while waiting. Each input is limited to 256 KiB, 20,000 syntax-tree nodes, depth 128 and 2,048-character number tokens. Show the first 100 differences. Expected JSON is literal; arbitrary scripts and automatic sends are outside this feature.

Download `.deb` for Ubuntu 24.04 x64, `.exe` for Windows x64 or `.AppImage` for Linux x64 and verify `SHA256SUMS.txt`. Installed use needs no developer Node/npm or account. Default Chromium UI language is English; Persian/Unicode request and response text remains supported.

## Verification

Fresh native build and installation evidence will be recorded here before publication. The publisher requires successful Ubuntu 24.04 and Windows Server 2022 jobs from the same source SHA and verifies all three installer checksums.

Hosted Windows Server checks do not establish Windows 11 acceptance. Full network-isolated/manual native chooser and uninstall/reinstall acceptance is not repeated for these installer bytes. Default AppImage FUSE launch and actual Postman GUI import remain unverified. Transfer tests control chooser responses while using real IPC/file services. Packages are unsigned; Windows may show reputation prompts.

Postman support remains the documented Collection v2.1 JSON subset. Auth literals, sensitive variable values, local file paths/selections, actual responses and response-test samples are omitted from exports. Ordinary URL/query/body/plain-variable text can contain credentials, so review exported files before sharing. Body profiles require 0.4.0 or newer readers. New expected-response configuration requires 0.5.0 or newer readers when reopening a local database. The repository retains its `UNLICENSED` designation.
