# TASK-017 — Documented redirect policy

Status: done. Date: 2026-10-05. TASK-016 was done and the working tree was clean at inspection. Only TASK-017 was executed.

## Changes

- Added a main-only redirect wrapper around the existing bounded native single-hop transport. Redirects OFF retains the original response. ON follows only 301/302/303/307/308 with Location, resolves against the current URL and permits at most five followed hops. Final response reports final URL, hop count and duration measured from the same monotonic start across all hops.
- Each replay plan freezes its metadata/header rows and owns private defensive body-byte copies. It never rematerializes variables, reads edited configuration between hops or mutates the original snapshot. 303 changes methods to GET except HEAD; 301/302 change only POST to GET; 307/308 preserve methods and original UTF-8 bytes. Switching to GET removes body and content/entity headers, including framing and body-related Expect/Trailer headers.
- Origin changes permanently remove Authorization, Proxy-Authorization and Cookie case-insensitively from the current plan, including return to the first origin. Host is regenerated by the single-hop engine. Response Set-Cookie does not become a request Cookie.
- Invalid targets, URL credentials/fragments and unsupported schemes fail before the next connection; HTTPS to HTTP fails with REDIRECT_DOWNGRADE. Loops/overflow fail with REDIRECT_LIMIT. Errors use fixed sanitized messages. The same lifecycle AbortSignal applies to every hop, with an abort check before starting the next one.
- ExecutionService now uses the wrapper and accepts redirects ON. Its existing ownership, acceptance handshake, busy guard and exactly-once terminal slot release remain intact. The temporary unsupported-ON expectations in existing execution tests were updated to actual redirect acceptance/completion.
- Added local two-origin redirect fixtures and a private main-only request-factory injection for verified HTTPS unit tests. Tests trust only the existing public fixture certificate; production uses normal native HTTPS with rejectUnauthorized:true. No renderer/preload CA option, TLS bypass, package/lockfile change, cookie jar, response UI or later task implementation.
