# Adjustable request/response panels — 2026-10-10

User authorized a toggle between vertical/stacked and horizontal/side-by-side request Body and response, with adjustable relative sizes. This is a post-task UI enhancement. Preserved existing uncommitted JSON presentation/icon work, task statuses and historical installer evidence.

## Changes

- Added a local layout toolbar above the request editor: **Stacked / Side by side**, with an accessible pressed state. Stacked is the default; side by side places the full request editor (including Body and existing field tabs) left of the response.
- CSS grid splits available space proportionally. Both regions scroll independently and remain mounted, preserving draft text, inactive body modes, selected tabs, response Raw/Pretty state and execution snapshot ownership when switching direction.
- Pointer capture makes the divider draggable in either axis. A labeled focusable separator exposes orientation and current request/response percentages; arrows resize, Shift uses a larger step, Home/End go to 20%/80% limits. Both panels remain present. Response Smaller/Larger adjusts height or width along the active axis, replacing the previous response-only native resize corner.
- Separate ratios retained per orientation during this app session: initial request share 55% stacked, 50% side by side. They are intentionally not persisted or included in workspace exports. Ratios scale with window size. Switching layout neither saves nor sends/cancels a request.
- Request URL/actions wrap in narrower panels. No package, IPC, SQLite migration, network, security or phase-2 change. UI specification, user guide and decision record updated.
